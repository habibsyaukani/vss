Automated daily scheduler to pull historical idle alarm data from last 7 days.

================================================================================
                        SCHEDULER CONFIGURATION
================================================================================

Location: app/Console/Kernel.php (line 38-60)

Schedule Details:
  Command: howen:pull-alarms-date-range
  Trigger: Daily at 3:00 AM (03:00)
  Mode: Parallel (5 concurrent connections)
  Pages: 30 (comprehensive coverage)
  Date Range: Last 7 days
  Error Handling: Logs both success and failure

Execution Pattern:
  - Every day at 3 AM, system pulls last 7 days of data
  - Uses parallel fetching (33x faster)
  - updateOrCreate prevents duplicates
  - Logs result to storage/logs/laravel.log

Performance Expected:
  - Duration: ~5-10 seconds (parallel mode)
  - Data fetched: ~2,100-2,800 records/day
  - Resources: Light (background process)

================================================================================
                        WHAT DATA GETS PULLED
================================================================================

Every Day at 3 AM:

  Data Range: Last 7 days
    Example: If today is June 4, pulls from May 28-June 4
    Tomorrow: If today is June 5, pulls from May 29-June 5

  Data Coverage:
    - All alarm records (from Howen API)
    - Type 32 alarms (Idle type)
    - Processed idle_alarms (validated)

  Typical Results:
    - Records fetched: 2,100-2,800
    - Type 32 identified: ~200-300
    - Valid idle events: ~50-100
    - Processing time: 5-10 seconds

  Data Update Strategy:
    - Uses updateOrCreate by GUID (no duplicates)
    - Existing records: NOT re-imported (skipped)
    - New records: Added automatically

================================================================================
                        OPTIONAL: CUSTOMIZE SCHEDULE
================================================================================

If you want to change the schedule, edit app/Console/Kernel.php around line 38:

CHANGE TIME (default 3 AM):
  From: ->dailyAt('03:00')
  To:   ->dailyAt('02:00')  // 2 AM
  Or:   ->dailyAt('23:00')  // 11 PM

CHANGE DATE RANGE (default 7 days):
  From: --from => now()->subDays(7)->format('Y-m-d'),
  To:   --from => now()->subDays(30)->format('Y-m-d'),  // 30 days
  Or:   --from => now()->subDays(1)->format('Y-m-d'),   // 1 day (yesterday only)

CHANGE FREQUENCY (default daily):
  From: ->dailyAt('03:00')
  To:   ->twiceDaily(3, 15)    // 3 AM and 3 PM
  Or:   ->everyTwoHours()      // Every 2 hours
  Or:   ->everyFourHours()     // Every 4 hours

CHANGE PARALLELISM:
  From: '--concurrency' => 5,
  To:   '--concurrency' => 3,   // More conservative
  Or:   '--concurrency' => 10,  // More aggressive (max)

After changes:
  1. Save file
  2. No restart needed (Laravel reloads)
  3. Check: php artisan schedule:list

================================================================================
                        TROUBLESHOOTING
================================================================================

❌ ISSUE: Scheduler not running
✅ SOLUTION: 
   1. Verify server has cron/scheduler running
   2. Check: ps aux | grep "schedule:run"
   3. Start: php artisan schedule:work (for testing)
   4. Production: Add to crontab

❌ ISSUE: Data not being pulled
✅ SOLUTION:
   1. Check logs: tail -f storage/logs/laravel.log
   2. Test manually: php artisan howen:pull-alarms-date-range --from=2026-05-27 --to=2026-06-04 --parallel --wait
   3. Check Howen API: Test HowenAuthService
   4. Check queue: php artisan queue:listen

❌ ISSUE: Pull takes too long (> 30 seconds)
✅ SOLUTION:
   1. Reduce page count: --pages 20 (from 30)
   2. Reduce date range: --subDays(3) (from 7)
   3. Increase concurrency: --concurrency 10 (from 5)
   4. Check network: ping ptdigital.co.id

❌ ISSUE: Getting duplicate records
✅ SOLUTION:
   This shouldn't happen (protected by updateOrCreate by GUID)
   If it does: Database corruption, contact admin

❌ ISSUE: Pull fails at 3 AM but works manually
✅ SOLUTION:
   1. Check system time: date
   2. Check timezone in .env: APP_TIMEZONE
   3. Check cron timezone: timedatectl
   4. Logs might be rotated: check other log files

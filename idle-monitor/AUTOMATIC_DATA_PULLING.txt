SCHEDULE EXPLANATION
================================================================================

Why this schedule?

✓ Token refresh every 25 minutes:
  - Howen token expires after 30 minutes
  - Refresh before expiry prevents errors
  - Automatic and safe

✓ Import alarms every 2 minutes:
  - Fast data pulling
  - Incremental (no duplicates)
  - Catches all events quickly
  - Safe with rate limiting

✓ Process idle every 5 minutes:
  - Validation and calculation
  - Create reports from raw data
  - Depends on ImportAlarmJob first

✓ Sync devices every 1 hour:
  - Device list doesn't change often
  - Once per hour is enough
  - Finds new vehicles automatically

Total load: ~4 minor tasks per 5 minutes
Result: Low CPU usage, reliable operation

================================================================================
TROUBLESHOOTING
================================================================================

Problem: "Nothing is happening"
Solution:
  1. Check Terminal 2 is running: php artisan schedule:work
  2. Check for errors in terminal
  3. Check logs: storage/logs/laravel.log
  4. Verify .env has HOWEN_API_URL and credentials

Problem: "Tasks not running at scheduled time"
Solution:
  1. Verify Terminal 2 running with schedule:work
  2. Check server time is correct
  3. Check Laravel logs for errors
  4. Try manual: php artisan queue:work

Problem: "Getting API errors from Howen"
Solution:
  1. Check .env credentials: HOWEN_USERNAME, HOWEN_PASSWORD
  2. Verify internet connection
  3. Check if Howen API is up
  4. See logs for exact error

Problem: "Database errors"
Solution:
  1. Check MySQL is running (Laragon)
  2. Check database 'vss' exists
  3. Check migrations are complete
  4. Run: php artisan migrate

Problem: "Performance issues"
Solution:
  1. Monitor: Terminal 2 should show tasks
  2. Check queue: php artisan queue:work
  3. Check logs for slow queries
  4. Reduce schedule frequency if needed

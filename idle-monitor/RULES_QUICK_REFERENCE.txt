🛡️ THE 5 GOLDEN RULES (NEVER BREAK THESE)

1. JANGAN MERUSAK FITUR YANG SUDAH BERJALAN
   - Tidak boleh mengubah fitur yang sudah berfungsi
   - Tidak boleh menghapus fitur yang sudah digunakan
   - Tidak boleh refactor komponen yang sudah stabil

2. JANGAN MENGHAPUS DATA YANG SUDAH ADA
   - Tidak boleh DROP TABLE
   - Tidak boleh TRUNCATE TABLE
   - Tidak boleh DELETE tanpa WHERE
   - Tidak boleh php artisan migrate:fresh

3. JANGAN MENGUBAH FITUR YANG TIDAK DIMINTA
   - Fokus pada task yang diminta saja
   - Jangan mengubah komponen lain
   - Jangan melakukan perubahan "bonus"

4. FOKUS HANYA PADA TASK YANG DIMINTA
   - Scope harus jelas
   - Tidak ada perubahan di luar scope
   - Jika perlu ubah scope, tanya dulu

5. SEMUA PERUBAHAN HARUS BACKWARD COMPATIBLE
   - Tidak boleh breaking changes
   - API harus tetap support request lama
   - Database harus tetap support data lama

DATABASE PROTECTION CHECKLIST
================================================================================

❌ DILARANG MUTLAK:

php artisan migrate:fresh              ❌ Akan menghapus SEMUA data
php artisan db:wipe                    ❌ Akan menghapus SEMUA database
php artisan migrate:reset              ❌ Akan menghapus semua migrations
DROP TABLE table_name;                 ❌ Akan menghapus table
TRUNCATE TABLE table_name;             ❌ Akan menghapus semua data
DELETE FROM table WHERE 1=1;           ❌ Akan menghapus semua data
ALTER TABLE table DROP COLUMN;         ❌ Akan menghapus kolom (data hilang)

✅ YANG BOLEH:

1. Membuat migration BARU:
   php artisan make:migration add_column_to_table
   
2. Tambah kolom (tidak merusak yang lama):
   Schema::table('table_name', function (Blueprint $table) {
       $table->string('new_column')->nullable();
   });

3. Tambah index (improve performa):
   Schema::table('table_name', function (Blueprint $table) {
       $table->index('column_name');
   });

4. Tambah data dengan aman:
   INSERT INTO table VALUES (...);
   
5. Update data dengan WHERE clause:
   UPDATE table SET field=value WHERE condition;

6. Delete data dengan ID spesifik:
   DELETE FROM table WHERE id = 123;

[ ] Task dijelaskan dengan jelas?

[ ] Ada batasan scope?

STEP 2 - ANALYZE EXISTING CODE (5 menit)

STEP 3 - PLAN THE CHANGES (5 menit)

[ ] Database perubahan apa? (create table, add column, dll)
[ ] API perubahan apa? (new endpoint, new field, dll)
[ ] Ada breaking changes?

STEP 4 - RISK ASSESSMENT (2 menit)
[ ] Risk level: GREEN / YELLOW / RED?

STEP 7 - VERIFY (2 menit)

================================================================================
COMMON MISTAKES TO AVOID
================================================================================

❌ MISTAKE 1: Modifying old migrations
   WRONG: Edit 2026_06_03_create_users_table.php
   RIGHT: Create new 2026_06_04_add_column_to_users.php

❌ MISTAKE 2: Using migrate:fresh
   WRONG: php artisan migrate:fresh
   RIGHT: php artisan migrate (for new migrations only)

❌ MISTAKE 3: Deleting columns directly
   WRONG: ALTER TABLE users DROP COLUMN role;
   RIGHT: Create new migration with dropColumn()

❌ MISTAKE 4: Changing API response
   WRONG: Change 'data' field name to 'records'
   RIGHT: Add new field, keep old field

❌ MISTAKE 5: Modifying protected files
   WRONG: Change app/Jobs/ImportAlarmJob.php
   RIGHT: Only if explicitly requested

❌ MISTAKE 6: Scope creep
   WRONG: Task "Add Device Group" → also refactor User model
   RIGHT: Task "Add Device Group" → only Device Group related

❌ MISTAKE 7: No backward compatibility
   WRONG: Update API to new version only
   RIGHT: Support both old and new version

❌ MISTAKE 8: Breaking changes without notice
   WRONG: Delete old API endpoint quietly
   RIGHT: Keep old endpoint, add new version, deprecate old

================================================================================
QUICK DECISION TREE
================================================================================

Need to make a change?

1. Is it part of the requested task?
   NO  → Don't do it (scope creep)
   YES → Go to step 2

2. Will it break existing features?
   YES → Find different approach (go back to step 1)
   NO  → Go to step 3

3. Will it delete data?
   YES → Need explicit approval
   NO  → Go to step 4

4. Is it backward compatible?
   NO  → Make it backward compatible (go back to step 3)
   YES → Go to step 5

5. All checked?
   YES → Implement it ✅
   NO  → Go back through steps
